# 스터디 자료 작성 템플릿 & 규칙

모든 챕터 노트(`partX_.../0N_.../0N_*.md`)는 아래 구조와 규칙을 따른다.

---

## 이 책은 장마다 성격이 다르다 — 템플릿을 골라 쓴다

> **아래 유형 표는 SLAM Handbook 의 실측값이다.** 새 책에 이 킷을 쓸 때는
> 그 책의 챕터별 수식 개수를 직접 세어 다시 채워라. 세는 법:
> ```bash
> pdftotext book.pdf - | grep -oE '\(([0-9]{1,2})\.[0-9]{1,3}\)' \
>   | grep -oE '^\([0-9]{1,2}' | sort | uniq -c
> ```
> 유형이 하나뿐인 책(전부 유도형 등)이면 이 절을 지우고 3단 구조만 남겨도 된다.

SLAM Handbook 은 70명이 쓴 책이고 파트마다 밀도가 완전히 다르다. 챕터별 번호매김
수식 개수를 실측하면 세 덩어리로 갈린다.

| 유형 | 장 (괄호 = 수식 개수) | 쓸 템플릿 |
|---|---|---|
| **A. 유도형** | 1(66) · 2(104) · 3(104) · 4(70) · **6(146)** · 11(136) · 12(75) · 16(72) | 아래 **3단 구조** |
| **B. 서베이형** | 5(18) · 7(15) · 8(5) · 9(16) · 10(4) · 13(32) · 14(8) · 15(4) · 17(12) · 18 | 아래 **5단 구조** |
| **C. 지도형** | Prelude I · II · III · Epilogue | 파트 조망 — 자유 구성 |

**한 템플릿으로 밀어붙이면 절반이 헛돈다.** Ch8(LiDAR)은 669쪽 책에서 수식이 5개다.
거기에 "2. 수식/유도"를 두면 빈 껍데기가 되고, Ch6(146개)에 서베이 틀을 씌우면
정작 유도를 못 담는다.

## 챕터 머리 블록 (모든 유형 공통)

책은 "chapters build on one another"라고 하면서 **어느 장이 어느 장을 전제하는지는
알려주지 않는다.** 처음 읽는 사람에게 이게 제일 큰 벽이다. 노트 맨 위에 고정으로 둔다.

```markdown
# 8장. LiDAR SLAM

> **원문 범위**: 책 p.224~249 (8.1~8.5절). 유형 B (서베이형).
> **먼저 필요한 것**: 1장(팩터그래프) · 5장(dense map 표현)
> **여기서 처음 나오는 것**: point-to-plane ICP · ScanContext · deskewing
> **나중에 쓰이는 곳**: 9장(radar odometry 가 같은 뼈대) · 16장(semantic 융합)
> **절 순서**: 책 순서 그대로. 재배치 없음.
```

의존성은 **추측하지 말고 원문에서 확인한다.** 그 장이 실제로 참조하는 장 번호를
`check_refs.py` 가 잡아 주므로, 노트를 다 쓴 뒤 대조해 채워 넣어도 된다.

## 템플릿 구조

```
## 1. 개념적 이해

(한국어 설명. 새로 등장하는 용어는 처음 나올 때 "한국어 설명(English term)" 형태로 병기.
 수식은 최소화하고 비유/직관 위주로 서술.)

## 2. 수식/유도

### 전체 유도 과정 (먼저 한 번에)

(관련된 수식 전체를 (1), (2), (3)... 번호를 매겨 설명 없이 연속으로 먼저 제시)

### 단계별 설명 (생략 없이)

**(1) ...**
(수식 (1)에 대한 설명)

**(2) ...**
(수식 (2)에 대한 설명. 이 유도에서 처음 쓰이는 도구/개념이 있으면
 그 개념을 먼저 설명하고 나서 수식으로 연결 — 아래 "생략 금지 규칙" 참조)

...

## 3. 예제/실습

(구체적 숫자를 사용한 예제. 계산 과정 전 단계 표시.
 가능하면 책에 나온 예제를 우선 사용. 마지막에 연습문제 또는 짧은 코드 스니펫.)
```

### 유형 B — 서베이형 5단 구조

Ch8(LiDAR)처럼 수식이 거의 없고 **인용 나열이 본문인** 장에 쓴다.
그대로 옮겨 적으면 읽고 나서 아무것도 할 줄 모르는 노트가 된다.

```
## 1. 문제 정의

(이 모달리티/주제가 정확히 무엇을 푸는가. 왜 별도 장인가.
 다른 센서로는 왜 안 되는가 — 물리적 한계까지 짚는다.)

## 2. 계보도

(방법들의 분기 구조. "누가 무엇의 한계를 고쳤나"의 사슬로 정리한다.
 단순 나열이 아니라 **표 + 인용번호**로. 인용은 [568] 처럼 원문 그대로 적으면
 자동으로 카드가 된다.)

| 방법 | 언제 | 앞선 것의 무엇을 고쳤나 | 남은 한계 |
|---|---|---|---|
| ScanContext[568] | 2018 | ... | ... |

## 3. 대표 방법 깊게                                    ★ 이 템플릿의 핵심

(계보도에서 1~2개를 골라 **유형 A 수준으로 직접 유도한다.**
 책이 한 문단으로 넘긴 것을 원논문까지 가서 편다.
 기준점이 하나 서면 나머지 나열이 그 위에서 읽힌다.)

## 4. 비교와 선택

(언제 무엇을 쓰나. **각각이 실패하는 조건**을 반드시 적는다 —
 서베이가 잘 안 적는 부분이고, 실무에서 제일 필요한 부분이다.)

## 5. 직접 확인

(데이터셋 · 공개 구현 · 재현 과제. 링크는 refs.json 의 번호로 남긴다.)
```

**3번을 건너뛰지 마라.** 이걸 빼면 그냥 목록을 한국어로 옮긴 것이 된다.
무엇을 고를지는 그 장의 `Further Readings` 절과 인용 빈도를 보고 정한다.

### 절마다 유연하게 적용한다

- 수식이 없는 절(개괄·요약·문헌)은 **1과 3만** 있어도 된다
- 알고리즘이 중심인 절은 2를 "### 2. 알고리즘"으로 바꿔도 된다
- **다만 내용이 있는 절에는 예외 없이 연습문제 1개 이상**을 둔다 (아래 예제/실습 규칙).
  단 **이 책에는 연습문제가 없고 Example 도 669쪽에 19개뿐**이다. 그래서 유형별로 나눈다.

  | 유형 | 무엇을 둘 것인가 |
  |---|---|
  | A (유도형) | 연습문제 또는 검산 스니펫 — 직접 출제한다 |
  | B (서베이형) | **재현 과제** 또는 **판단 문제** ("이 환경에서 LiDAR 와 Radar 중 무엇을 고르고 왜인가") |
  | C (지도형) | 그 파트의 장들을 한 장의 그림/표로 잇는 정리 과제 |

### 책의 절 순서를 바꿔도 된다 — 대신 밝힌다

이해 순서가 책 순서와 다르면 재배치한다. 단 **헤더에 책의 원래 절 번호와 쪽번호를 함께 적고**,
노트 상단에 재배치 사실을 명시한다.

> 예: 어떤 장에서 책은 "밀도 계산 → 표집" 순이었지만, 표집이 훨씬 직관적이라
> "유도 → 표집 → 밀도 계산" 순으로 배치하고 그 이유를 상단에 적었다.

## 언어 규칙

- **섹션 1 (개념적 이해)**: 한국어 설명 + 원본 영단어 병기. 예: "사전 확률(prior)", "가능도(likelihood)".
  한글 번역이 어색하거나 못 알아볼 수 있는 용어는 병기를 통해 원문을 같이 남긴다.
- **섹션 2, 3 (수식/유도, 예제/실습)**: 수학적·전문 용어는 한국어로 억지로 번역하지 않고 영어를
  그대로 사용한다. **문장 자체는 한국어로 서술하되 용어는 영어.**

### 용어표를 운영한다

**이 문서 아래쪽에 "절대 번역하지 않는 용어" 표를 만들고, 새 용어가 나올 때마다 갱신한다.**

| 쓸 것 | 쓰지 말 것 |
|---|---|
| (영어 용어) | (어색한 한국어 번역어) |

**판단 기준**: 한국어 교재에서 그 번역어가 **실제로 통용되는가?** 아니라면 영어를 쓴다.

- 통용되는 것의 예: 공분산, 조건부확률, 정규분포, 기댓값, 편미분, 정규화 상수
- 통용되지 않는 것의 예: (분야마다 다르다 — 처음 몇 챕터를 쓰며 직접 판단해 채운다)

**품사를 구분하라.** 명사는 영어로 쓰더라도 동사·형용사형은 한국어가 자연스러운 경우가 많다.
경계가 모호하면 표에 명시한다.

| 원문 | 노트에 쓸 것 | 쓰지 말 것 |
|---|---|---|
| 명사 `projection` | **projection** | 사영 |
| 동사 `project` | **투영하다** | 사영하다 |

> **판단에 멈칫했다면 그건 규칙이 모호하다는 증거다.** 본문을 고치기 전에 규칙에 경계를 명시하라.

### 챕터를 끝낼 때마다 훑는다

```bash
for t in <금지어1> <금지어2> <금지어3>; do
  echo "$t: $(grep -o "$t" part*/*/*.md | wc -l)건"
done
```

여러 세션에 걸쳐 쓰면 표기가 반드시 흔들린다. 이 검사로 한 번에 **31건**이 나온 적도 있다.

## 수식/유도 규칙 (생략 금지)

1. 해당 개념/알고리즘과 관련된 유도 전체를 번호를 매겨(`(1)`, `(2)`, ...)
   **설명 없이 먼저 통으로 보여준다.**
2. 그 다음, 번호별로 하나씩 짚어가며 설명한다. 이때:
   - 결과 수식만 제시하지 않고, **왜 그 수식이 나오는지**(정의 적용, 이전 단계 대입, 항등식 변형 등)를
     항상 명시한다.
   - 유도 중 **처음 등장하는 수학적 도구/개념**(예: marginalization, chain rule, Taylor expansion,
     회전행렬 등)이 있으면, 그 개념을 곧바로 수식으로 넘어가지 않고
     **개념 설명 → 수식** 순서로 별도 문단(인용구 `>` 등으로 구분)을 만들어 짚어준다.
   - 정의(definition)와 유도된 결과(derived result)를 구분해서 명시한다
     (예: "이건 정리가 아니라 definition이다").
3. 알고리즘 의사코드는 **원문 표의 이미지와 코드 블록을 함께** 싣고, 라인별로 무엇을 하는지 짚는다.

## 원문 참고 규칙 (기억에 의존 금지)

- 스터디 자료를 작성할 때는 **항상 `ref/`의 원본 PDF를 직접 열어 확인한 내용을 근거로 작성한다.**
  기억이나 일반 지식에 의존해서 쓰지 않는다. 수식, 알고리즘 의사코드, 변수 표기, 절 번호, 예제 수치는
  반드시 원문과 대조한다.
- 원문에서 인용/참고한 위치는 **절 번호와 책 쪽번호로 명시**한다 (예: "책 2.4.3절, p.31").
  `tools/check_refs.py`가 이 표기를 읽어 검사한다.

### 시작 전에 반드시 확인할 두 가지

```bash
pdfinfo "ref/책.pdf" | grep Pages                  # ① 총 쪽수
pdftotext -f 60 -l 60 "ref/책.pdf" - | head -3     # ② 페이지 오프셋
```

**둘 다 추측하지 마라.** 앞·중간·뒤 세 곳에서 오프셋을 검증하고 `kit.conf`에 적는다.
이유와 사고 사례는 [`3_Pitfalls.md`](3_Pitfalls.md) A1·A2.

### 원문이 없는 범위를 써야 할 경우

1. 먼저 사용자에게 해당 범위의 원문 확보를 요청한다.
2. 원문 없이 진행해야 한다면, 그 사실을 노트 상단에 명시하고 원문 대조가 필요한 부분을 표시한다.

## 예제/실습 규칙

- 가능하면 **책에 나온 예제를 우선 재사용**한다.
- 계산은 중간 단계를 생략하지 않고 전부 보여준다.
- **내용이 있는 절마다 연습문제 1개 이상**, 또는 검증용 짧은 코드 스니펫을 포함한다.

### 손계산은 반드시 코드로 검산한다

**예제를 쓴 뒤 같은 계산을 코드로 다시 해서 대조한다. 예외 없이.**

한 챕터의 예제에서 **7곳이 틀린 적이 있다.** `atan2` 값 하나가 어긋나면서 그 뒤 행렬 곱이
연쇄로 전부 잘못됐다. 손으로 쓴 중간값을 반올림해 다음 계산에 넣으면 오차가 누적된다.

```python
# 노트에 쓴 값과 나란히 출력해 눈으로 대조한다
print(f"  Sigma_bar = {Sigma_bar}   (노트: [[0.198, ...]])")
```

부수 효과 — 이 검산 코드가 그대로 노트의 "검증용 스니펫"이 된다.

## 보충 설명은 본문에 풀지 말고 aside 카드로

이 스터디는 **SLAM 을 처음 보는 사람 기준**이라 책이 전제하고 넘어가는 것을 채워야 한다.
그런데 본문에 그대로 풀면 정작 그 장이 말하려는 것이 묻히고, 생략하면 읽다가 막힌다.

**aside 카드로 뺀다.** 본문에는 점선 밑줄만 남고 클릭하면 오른쪽에서 열린다 —
아는 사람은 지나가고, 모르는 사람은 그 자리에서 편다.

```markdown
MAP 추정은 [[map-estimation]] 이다.          ← 전역 카드 (여러 장이 공유)
[[se3|SE(3) 위]]에서 정의된다.                ← 표시할 말을 바꿀 때
ScanContext[568] 가 이 방식이다.              ← 인용은 아무것도 안 해도 카드가 된다
```

| 카드로 뺄 것 | 본문에 쓸 것 |
|---|---|
| 책이 **전제하고 넘어가는** 배경 (SE(3), Schur complement, SDP) | 그 장이 **가르치려는** 것 |
| 다른 장에서 다뤘고 여기선 쓰기만 하는 것 | 이 장에서 처음 유도하는 것 |
| 용어의 유래, 표기 충돌, 원문 오기 | 유도의 각 단계 |

**판단 기준**: 그것을 아는 독자에게 군더더기로 느껴지면 카드로 뺀다.

> ⚠️ **카드 안에서도 생략하지 않는다.** 분량을 아끼려고 만든 장치가 아니라
> **본문의 초점을 지키려고** 만든 장치다. 위의 "생략 금지" 규칙이 카드 안에서도
> 그대로 적용된다. 원문을 옮겼으면 카드 안에도 `(책 p.152)` 를 붙인다.

작성법·저장 위치·확인 방법은 [`tools/asides/_GUIDE.md`](tools/asides/_GUIDE.md).

## 포맷/파일 규칙

- 수식은 LaTeX 문법(`$...$`, `$$...$$`)으로 작성 (MathJax 렌더링 기준).
- 폴더 구조는 `0_Contents.md` 장 번호를 그대로 따른다 (`partX_.../0N_챕터명/0N_챕터명.md`).
- 책 원본 이미지는 해당 챕터 폴더의 `images/`에서 참조한다.
  파일명은 `fig<장>_<번호>_<설명>.png`, `table<장>_<번호>_<설명>.png` 형식으로 통일한다.
- 이미지 바로 아래에 **캡션을 한국어로 옮기고 쪽번호를 붙인다.**


## 절대 번역하지 않는 용어

> **이 표는 스터디를 시작할 때 비어 있다.** 챕터를 쓰면서 마주치는 용어를 계속 추가한다.
> 아래는 수리·통계 분야에서 대체로 통하는 출발점이다. 분야가 다르면 지우고 새로 채워라.

| 쓸 것 | 쓰지 말 것 |
|---|---|
| unimodal / multi-modal / bimodal | 단봉 / 다봉 / 이봉 |
| mode | 봉우리 (분포의 최빈값을 뜻할 때) |
| marginalization | 주변화 |
| prior / posterior / likelihood | (첫 등장 시 "사전 확률(prior)"처럼 병기 허용, 이후 영어) |
| Jacobian | 야코비안 |
| bijective mapping | 전단사 사상 |
| point mass distribution | 점 질량 분포 |

**반면 아래는 한국어가 표준이므로 그대로 쓴다**: 공분산, 결합확률, 조건부확률, 정규분포, 확률변수,
기댓값, 전확률 정리, 충분통계량, 곡률, 귀납법, 정방행렬, 편미분, 항등식, 정규화 상수.
