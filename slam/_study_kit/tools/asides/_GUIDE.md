# aside 카드 (포스트잇) 작성 가이드

책이 설명 없이 쓰고 지나가는 개념을 **본문 흐름을 끊지 않고** 채우는 장치다.
본문에는 점선 밑줄만 남고, 클릭하면 오른쪽에서 카드가 열린다.

## 왜 본문에 안 쓰고 카드로 빼는가

이 스터디는 SLAM 을 처음 보는 사람 기준이라 보충할 것이 많다. 그런데 그것들을
본문에 그대로 풀어 쓰면 **정작 그 장이 말하려는 것이 묻힌다.** 반대로 생략하면
읽다가 막힌다. 카드는 둘 다 피한다 — **아는 사람은 그냥 지나가고, 모르는 사람은
그 자리에서 편다.**

그래서 **카드 안에서는 생략하지 않는다.** 분량을 아끼려고 만든 장치가 아니다.
본문 규칙(`2_Template_and_Rule.md`)의 "생략 금지"가 카드 안에서도 그대로 적용된다.

## 쓰는 법

### 1) 참조 — 본문 아무 데서나

```markdown
이 문제는 [[se3]] 위에서 정의된다.
[[map-estimation|MAP 추정]]으로 풀면 최소제곱이 된다.
```

- `[[이름]]` — 카드 제목이 그대로 본문에 표시된다
- `[[이름|표시할 말]]` — 문장에 맞춰 다르게 쓸 때
- 같은 카드를 여러 번, 여러 챕터에서 참조해도 된다

### 2) 정의 — 두 곳 중 하나

**전역** (여러 챕터가 함께 쓰는 개념) — `_study_kit/tools/asides/이름.md`

```markdown
---
title: SE(3) — 3차원 강체 변환군
---

내용. 마크다운을 그대로 쓴다. 수식 $R \in SO(3)$ 도 된다.
```

**챕터 로컬** (그 장에서만 쓰는 것) — 챕터 `.md` 안, 보통 파일 끝

```markdown
<!--aside:chi2 카이제곱 검정과 자유도-->
내용을 여기에.
여러 문단, 수식 $$\chi^2_{n}$$, 목록, 표 전부 된다.
<!--/aside-->
```

같은 이름이 양쪽에 있으면 **챕터 로컬이 이긴다.**

### 3) 인용 — 아무것도 안 해도 된다

본문에 `[568]` 이라고 원문 그대로 적으면 `refs.json` 에서 찾아 자동으로 카드가 된다.

```markdown
ScanContext[568] 와 RING++[1212, 703] 가 이 방식이다.
```

→ 저자·연도·제목이 카드로 뜬다. `refs.json` 은 `build_refs.py` 가 만든다.
번호가 `refs.json` 에 없으면 빌드할 때 경고가 나온다.

## 무엇을 카드로 뺄 것인가

| 카드로 | 본문으로 |
|---|---|
| 책이 **전제하고 넘어가는** 배경 (SE(3), Schur complement, SDP) | 그 장이 **가르치려는** 것 |
| 다른 장에서 이미 다뤘고 여기선 쓰기만 하는 것 | 이 장에서 처음 유도하는 것 |
| 용어의 유래, 표기 충돌, 흔한 오해 | 유도의 각 단계 |
| 원문 오기 지적 | 원문 내용 |

**판단 기준**: 그것을 아는 독자가 읽었을 때 "군더더기"로 느껴진다면 카드로 뺀다.

## 규칙

- **한 카드에 한 개념.** 두 개를 담고 싶으면 카드를 둘로 나누고 서로 참조한다
- 카드 안에서도 원문 대조 규칙을 지킨다 — 책 내용을 옮겼으면 `(책 p.152)` 를 붙인다
- 책에 없는 배경 지식이면 그렇다고 밝힌다 (예: "책에는 없다. SDP 를 처음 본다면")
- 카드 안에서 다른 카드를 `[[이름]]` 으로 참조해도 된다
- 제목은 **한 줄**로. 길면 본문 참조 표시가 넘친다

## 확인

```bash
python3 _study_kit/tools/build_html.py <챕터>.md
```

빌드하면 아래를 알려 준다.

```
aside 카드 7개 (전역 5 · 로컬 2) · 인용 23개
⚠ 정의 없는 aside 참조: [[schur]]
⚠ refs.json 에 없는 인용: [9999]
```

정의가 없는 참조는 **빌드가 실패하지 않고 경고만** 낸다. 본문에는 회색 점선으로
표시되므로 렌더링을 눈으로 볼 때 바로 보인다. 아직 안 쓴 카드를 미리 참조해 두고
나중에 채우는 방식이어도 된다.
