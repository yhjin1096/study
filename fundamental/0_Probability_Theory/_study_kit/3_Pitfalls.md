# 실전에서 겪은 함정

책 한 권 분량의 스터디 노트(16,000줄·그림 118개·위젯 21개)를 만들며 **실제로 당한** 것들이다.
읽는 데 10분, 아끼는 시간은 며칠.

각 항목은 **증상 → 원인 → 대처** 순이다.

---

## A. PDF 다루기

### A1. 페이지 오프셋을 추측했다 ⚠️ 가장 비쌌던 실수

**증상** — 추출한 그림이 엉뚱한 페이지의 것이거나, 인용한 쪽번호가 실제와 어긋난다.

**원인** — 책에 인쇄된 쪽번호와 PDF 페이지 번호는 다르다. 표지·목차·서문 분량만큼 밀려 있다.
"대충 20쯤이겠지"로 시작하면 전 챕터가 어긋난다.

**대처** — 시작 전에 **앞·중간·뒤 세 곳 이상**에서 검증하고 `kit.conf`에 적는다.

```bash
pdftotext -f 60 -l 60 "ref/책.pdf" - | head -3     # 이 PDF 쪽의 인쇄 쪽번호는?
```

맨 윗줄이나 아랫줄에 쪽번호가 찍혀 있다. `PDF 페이지 − 인쇄 쪽번호`가 오프셋이다.
드물게 중간에 오프셋이 바뀌는 판형(부록·별지)도 있으니 뒤쪽도 확인한다.

### A2. PDF 총 페이지 수를 추측했다

**증상** — "PDF가 98페이지에서 끝난다"고 잘못 판단하고, 그 오류를 규칙 문서와 노트 여러 곳에
기록해 버렸다. 나중에 전부 되돌려야 했다.

**원인** — 특정 페이지에 내용이 있다는 사실은 **그 페이지가 마지막이라는 근거가 아니다.**
도구가 표시하는 페이지 수도 그대로 믿으면 안 된다.

**대처** — 한 줄이면 된다. 시작할 때 실행하고 `kit.conf`에 적어 둔다.

```bash
pdfinfo "ref/책.pdf" | grep Pages
```

### A3. 캡션 라벨이 조각나 있다

**증상** — 분명히 있는 `Table 3.2`를 추출 스크립트가 못 찾는다.

**원인** — PyMuPDF가 텍스트를 쪼개는 방식 때문에 라벨이 나뉜다. 두 가지 형태가 있다.

| 형태 | 예 |
|---|---|
| 한 줄 안의 여러 span | `['Table', ' 3.2']` |
| **같은 y인데 별도 line** | `line0='Table'`, `line1='3.2'` ← 이게 더 까다롭다 |

**대처** — `extract_figures.py`의 `find_captions()`는 **같은 높이(y 차이 2pt 이내)의 볼드 조각을
x 순으로 이어붙여** 라벨을 복원한다. 이미 반영돼 있으니 그대로 쓰면 된다.
직접 캡션을 찾는 코드를 쓸 일이 있으면 이 점을 기억하라.

### A4. 존재하지 않는 그림 번호가 있다

**증상** — `Figure 8.15`를 아무리 찾아도 없다. 스크립트 버그를 의심하며 시간을 쓴다.

**원인** — 저자가 번호를 건너뛴 것이다. 실제로 한 책에서 **Figure 3.1과 Figure 8.15 두 개가
통째로 없었다.**

**대처** — 의심되면 PDF 전문을 검색해 확정한다. 없는 것이 맞으면 `kit.conf` 메모에 남긴다.

```python
import fitz
doc = fitz.open(PDF)
print([p+1 for p in range(doc.page_count) if 'Figure 8.15' in doc[p].get_text()])
```

### A5. 페이지 전체가 스캔 이미지다

**증상** — `page.get_image_info()`가 반환하는 bbox가 `(0, 0, 576, 648)` — 페이지 전체다.
이걸 그림 영역으로 쓰면 페이지가 통째로 잘려 나온다.

**원인** — 일부 페이지가 벡터가 아니라 통짜 스캔 이미지다. 객체 bbox가 무의미해진다.

**대처** — 객체 bbox를 믿지 말고 **캡션 위치로 영역을 좁힌 뒤 픽셀 단위로 흰 여백을 트림**한다.
`extract_figures.py`가 이 방식이다. 스캔이든 벡터든 똑같이 동작한다.

### A6. 본문 중 언급이 캡션으로 잡힌다

**증상** — `Figure 6.2 shows a typical example of …` 같은 **본문 문장**이 캡션으로 검출되어,
같은 그림이 두 페이지에서 잡힌다.

**원인** — 문자열만 보면 캡션과 본문 언급이 구분되지 않는다.

**대처** — **폰트로 구분한다.** 캡션 라벨은 볼드(예: `Palatino-Bold` 9pt), 본문은 로만체 10pt다.
판형이 다르면 아래로 확인하고 스크립트의 조건을 맞춘다.

```python
for ln in page.get_text("dict")["blocks"][i]["lines"]:
    f = ln["spans"][0]
    print(f["font"], f["size"], "".join(s["text"] for s in ln["spans"])[:40])
```

### A7. 알고리즘 의사코드가 본문 문단으로 오판된다

**증상** — 알고리즘 표(pseudo-code)를 추출하면 영역이 `h=0.2pt`로 잡혀 실패한다.

**원인** — 추출 로직은 "컬럼 폭을 가득 채운 줄 = 본문 문단"으로 보고 그 아래를 그림 영역에서
제외하는데, 알고리즘 첫 줄(`1: Algorithm VeryLongAlgorithmName(인자, 인자, …)`)이 길어서
본문으로 오판된다.

**대처** — `^\d+:` 로 시작하는 줄은 본문 판정에서 제외한다(이미 반영). 그리고 영역 판정이
실패하면 머리글 아래 전체를 잡아 픽셀 트림에 맡기는 **폴백**을 둔다.

### A8. 캡션 규약이 책마다 다르다 ⚠️ 새 책을 시작할 때 첫 관문

**증상** — `--list`를 돌렸는데 아무것도 안 나온다.

**대처 1단계** — 캡션이 정말 없는 책인지 먼저 센다.

```python
import fitz, re
d = fitz.open(PDF); pat = re.compile(r'(Figure|Table|Fig\.|Example|Theorem)\s*\d')
hits = {}
for p in range(d.page_count):
    for m in pat.finditer(d[p].get_text()): hits[m.group(1)] = hits.get(m.group(1), 0) + 1
print(hits)      # 비어 있으면 캡션 규약이 없는 책이다
```

강의 노트·논문 모음처럼 **그림 번호를 아예 안 붙이는** 자료가 실제로 있다
(45쪽짜리 강의 노트에서 `Figure`·`Table`·`Fig.`가 **한 번도** 안 나온 경우를 만났다).
그런 책이면 그림 없이 노트만 쓰거나, 필요한 그림만 clip을 직접 지정해 뽑는다.

**대처 2단계** — 위에서 개수가 나왔는데 `--list`가 비었다면 **규약이 다른 것**이다. 실제 형식을 본다.

```python
import fitz, re
d = fitz.open(PDF)
for p in range(d.page_count):
    for blk in d[p].get_text("dict")["blocks"]:
        if blk.get("type") != 0: continue
        for ln in blk["lines"]:
            s = "".join(x["text"] for x in ln["spans"]).strip()
            if re.match(r'^(Figure|Fig\.|Table)\s*\d', s):
                f = ln["spans"][0]
                print(f'p{p+1}  font={f["font"]}  size={f["size"]:.1f}  {s[:70]!r}')
```

두 축으로 갈린다. 확인했으면 `kit.conf`에 적는다.

| 본 것 | 설정 |
|---|---|
| `Figure 6.3 설명` — 장 번호 + 일련번호 | `caption_style = chapter` |
| `Figure 3: 설명` — 문서 전체 연속 번호 (LaTeX article) | `caption_style = flat` |
| 라벨 폰트 이름에 `Bold` 가 있다 | `caption_bold = yes` |
| 없다 (예: `SFRM1000`) | `caption_bold = no` |

> **실제 사례** — A4 LaTeX article 문서에서 캡션이 `Figure 1: 설명`(장 번호 없음)이고 폰트가
> `SFRM1000`(볼드 아님)이라 기본 설정으로는 **19개 전부 놓쳤다.** `caption_style = flat`,
> `caption_bold = no` 로 바꾸자 **19개 모두** 잡혔다.

`caption_style = flat` 이면 그림 번호에 장 번호가 없으므로 `--chapter` 를 생략하고 `--pages` 로만
범위를 정한다.

그래도 안 잡히면 그 책이 쓰는 다른 규약(`Example 3`, `Theorem 2.1` 등)에 맞춰
`extract_figures.py`의 `caption_regex()`를 고친다.

### A9. 레이아웃 상수 맞추기

**판형이 다르면 기본값이 안 맞는다.** 킷의 기본값은 MIT Press 계열 단행본(**576×648pt**) 기준이다.
US Letter(**612×792pt**)나 A4는 컬럼 위치가 다르므로 반드시 다시 잰다. 첫 확인은 한 줄이면 된다.

```python
import fitz; print(fitz.open(PDF)[0].rect)      # 예: Rect(0, 0, 612, 792) → Letter
```

`kit.conf`의 `clip_x`·`header_y`·`body_x`를 맞추는 방법:

```python
import fitz
doc = fitz.open(PDF)
p = doc[<그림이 있는 PDF 쪽>-1]
print("page rect:", p.rect)                      # 판형 (예: 576×648)
for blk in p.get_text("dict")["blocks"]:
    if blk.get("type") != 0: continue
    for ln in blk["lines"]:
        b = ln["bbox"]; t = "".join(s["text"] for s in ln["spans"]).strip()
        if t: print(f"y{b[1]:7.1f}-{b[3]:6.1f} x{b[0]:6.1f}-{b[2]:6.1f}  {t[:50]}")
```

- `header_y` — 머리글(쪽번호·장 제목) 줄의 아래쪽 y보다 조금 큰 값
- `clip_x` — 본문 컬럼의 좌우. **서브패널 라벨 `(a)`가 컬럼보다 살짝 왼쪽에서 시작**하는 판형이
  많으니 왼쪽에 여유를 준다. 단 좌측 marginal note를 물면 안 된다
- `body_x` — 본문 문단이 채우는 폭. 컬럼보다 약간 안쪽으로 잡는다

### A10. 캡션이 있어도 bbox 추출이 나을 때가 있다

**증상** — 캡션 검출은 19개 전부 성공했는데, 뽑힌 그림 하나에 **바로 위 수식과 절 제목까지**
딸려 들어왔다.

**원인** — 캡션 기반 추출은 캡션에서 위로 올라가며 "본문 문단"을 만나면 거기서 자른다.
그런데 **절 제목은 컬럼 폭을 다 채우지 않아** 본문 문단으로 인식되지 않는다. 그래서 경계를
지나쳐 계속 위로 올라간다.

**대처** — 문서 안의 **이미지 객체 수와 그림 수가 1:1이면 bbox 방식이 훨씬 안전하다.**
먼저 개수를 세어 보고 결정한다.

```python
import fitz
doc = fitz.open(PDF)
n = sum(len(doc[i].get_image_info()) for i in range(len(doc)))
print("이미지 객체", n, "개")        # 그림 수와 같으면 extract_images_bbox.py 를 쓴다
```

벡터 그림(선으로 그린 도형)은 이미지 객체가 아니므로 이 방법이 통하지 않는다. 그때는
캡션 방식으로 가되 **뽑은 PNG를 전부 눈으로 확인**한다.

## B. 노트 쓰기

### B1. 손계산은 반드시 코드로 검산한다 ⚠️ 오류가 가장 많이 나온 곳

**증상** — 한 챕터의 예제에서 **7곳이 틀렸다.** `atan2` 값 하나가 어긋나면서 그 뒤 행렬 곱이
연쇄로 전부 틀렸다.

**원인** — 손으로 쓴 중간값을 반올림해 다음 계산에 넣으면 오차가 누적된다. 행렬 곱은 특히 위험하다.

**대처** — 예제를 쓴 뒤 **같은 계산을 코드로 다시 해서 대조**한다. 예외 없이.

```python
# 노트에 쓴 값과 나란히 출력해 눈으로 대조한다
print(f"  Sigma_bar = {Sigma_bar}   (노트: [[0.198,...]])")
```

부수 효과가 하나 더 있다 — 이 코드가 그대로 노트의 "검증용 스니펫"이 된다.

### B2. 인용에 쪽번호를 빠뜨린다

**증상** — 나중에 원문을 다시 찾을 때 어디였는지 몰라 전 챕터를 뒤진다.

**대처** — 원문을 옮긴 문장에는 예외 없이 `(책 p.167)`을 붙인다. 절 번호도 함께 적으면 더 좋다.
`check_refs.py`가 이 표기를 읽어 검사한다.

### B3. 같은 개념을 두 낱말로 쓴다

**증상** — 한 노트 안에서 `mode` 9번, `봉우리` 7번. 규칙표에 금지어로 적어 두고도 위반했다.
점검에서 31건이 나왔다.

**원인** — 여러 세션에 걸쳐 쓰면 표기가 흔들린다. 규칙표를 만들어 놓고도 안 본다.

**대처** — 챕터를 끝낼 때마다 금지어를 기계적으로 훑는다.

```bash
for t in 봉우리 사영 야코비안 혁신; do
  echo "$t: $(grep -o "$t" part*/*/*.md | wc -l)건"
done
```

### B4. 규칙의 경계가 모호하면 규칙을 고친다

**증상** — 규칙표에 `perception → 지각 금지`라 적혀 있는데, 동사 `perceive`를 옮긴
"지각하다"도 위반인지 판단이 안 선다.

**대처** — 판단에 멈칫했다면 그건 **규칙이 모호하다는 증거**다. 본문을 고치기 전에 규칙에
경계를 명시하라. (그 사례에서는 "명사만 금지, 동사·형용사형은 한국어 허용"으로 정리했다.)

### B5. 인용구 안의 `$$` 수식을 여러 줄로 쓰면 `>` 가 수식에 섞여 들어간다

**증상** — 인용구(`>`)로 만든 Tip 박스 안의 블록 수식이 이렇게 렌더링된다.

```
[Cxx Cxy]  >=  [I 0]  >  [Cxx Cxy]        ← 있지도 않은 > 기호가 수식 중간에 박힌다
```

**원인** — `build_html.py`는 마크다운 변환 **전에** `$$...$$` 를 통째로 보관(protect)한다.
인용구 안에서 수식이 여러 줄에 걸치면 두 번째 줄부터의 `> ` 가 수식 문자열 안에 포함된 채로
보관되고, 그 뒤 인용구 처리기가 `> ` 를 벗겨낼 기회를 잃는다.

**대처** — **인용구 안의 블록 수식은 반드시 한 줄로 쓴다.**

```markdown
> $$\begin{aligned} a &= b \\ &= c \end{aligned} \tag{90}$$      ← 한 줄. 길어도 상관없다
```

인용구 밖의 수식은 여러 줄로 써도 문제가 없다.

### B6. autoload 매크로 하나가 페이지 **전체** 수식을 죽인다 (그리고 해결하는 법) ⚠️ 증상이 엉뚱한 곳에서 나타난다

**증상** — 수식이 하나도 렌더링되지 않고 `$$...$$` 원본이 그대로 글자로 보인다. 문제의 매크로를 쓴 그
수식만이 아니라 **문서의 모든 수식**이 그렇다. 오류 메시지는 없다.

**원인** — `tools/vendor/tex-svg.js` 번들에는 base + ams 만 들어 있다. 그 밖의 패키지에 속한 매크로를
만나면 MathJax의 autoload가 CDN에서 해당 확장을 받아오려 하고, **오프라인이라 실패하면서 typeset
프라미스 전체가 죽는다.** 그 결과 페이지의 수식이 통째로 렌더링되지 않는다.

| autoload 대상 | 번들에 이어 붙이면? | 안 붙였다면 대신 |
|---|---|---|
| `\color` · `\textcolor` | **된다** (`color.js`, 8.6KB) | 색을 포기하거나 CSS 로 (아래) |
| `\boldsymbol` | **된다** (`boldsymbol.js`, 4KB) | `\pmb` (base 라 안전) |
| `\cancel` · `\bcancel` | 안 된다 (같은 방법으로도 실패) | 취소선 포기 |
| `\href` · `\enclose` · `\unicode` | 확인 안 함 | 쓰지 않는다 |

`\substack` · `\boxplus` · `\therefore` · `\leftrightarrows` · `\underline` · `\intercal` · `\boxed`는
ams 또는 base에 있으므로 **안전하다.** 새 매크로를 쓸 때는 아래 한 줄로 먼저 확인하라.

```bash
# 렌더링 여부는 눈이 아니라 DOM 개수로 확인한다
google-chrome --headless --disable-gpu --no-sandbox --virtual-time-budget=25000 \
    --dump-dom "file://$PWD/notes/노트.html" | grep -o '<mjx-container' | wc -l
```

> **오류 개수를 셀 때는 `<script>` 를 먼저 지워라.** MathJax 번들 소스 안에 `merror` 와
> `"data-mjx-error"` 라는 **문자열이 그대로 들어 있다.** 인라인된 2MB 번들을 통째로 grep 하면
> 실제 오류가 0 건이어도 각각 3건씩 잡혀서 "오류가 있다" 고 잘못 판단하게 된다.
>
> ```python
> body = re.sub(r'<script.*?</script>', '', dom, flags=re.S)   # 이 다음에 센다
> print(len(re.findall(r'data-mjx-error', body)))
> ```

> **덤으로** — 헤드리스 스크린샷으로 수식을 확인할 때 `--virtual-time-budget` 이 짧으면
> (2MB 번들 기준 10초 미만) MathJax가 끝나기 전에 캡처되어 **렌더링이 안 된 것처럼 보인다.**
> 20000 이상을 주고, 최종 판정은 위의 `<mjx-container` 개수로 하라.

**최소 예제로 확인하는 법** — 문서 전체를 이등분해 가며 찾지 말고 아래 세 줄짜리 페이지로 먼저
확인한다. 벤더 번들은 **같은 폴더로 복사**해서 상대 경로로 참조해야 한다
(`file://` 절대 경로로 참조하면 헤드리스에서 로드되지 않아 항상 0개로 나온다).

```html
<script>window.MathJax={tex:{inlineMath:[['$','$']]},svg:{fontCache:'global'}};</script>
<p>A: $\boldsymbol{\omega}$</p><p>B: $\pmb{\omega}$</p><p>C: $\mathbf{q}\otimes\mathbf{p}$</p>
<script src="tex-svg.js"></script>
```

A를 `\boldsymbol`로 두면 **셋 다 0개**, `\pmb`로 바꾸면 **3개**가 나온다. 그리고 `--dump-dom`을
grep 하면 MathJax가 주입한 `<script src=".../input/tex/extensions/boldsymbol.js">`가 보인다 —
없는 파일을 받으려다 죽는 순간이 눈에 잡힌다.


**색을 완전히 포기할 필요는 없다.** 위 제약은 **TeX 매크로**에 대한 것이다. 원문의 강조가
**수식 안이 아니라 산문**에 있다면 CSS 로 재현할 수 있고, 그 안에 인라인 수식이 섞여 있어도 된다 —
**MathJax 의 SVG 글리프는 `currentColor` 를 상속**하기 때문이다.

```html
<p style="color:#197fb2"><b>파란 문장 안의 수식 $\tau \oplus \mathbf{x}$ 도 같이 물든다.</b></p>
```

확인 결과 `getComputedStyle(mjx-container).color` 가 `rgb(25,127,178)` 로 상속되고 글리프도 그 색으로
칠해진다. `\color` 를 쓰지 않으므로 autoload 가 발동하지 않는다.
Lie Theory 스터디는 이 방법으로 원문의 파란 강조 12곳을 그대로 살렸다
(빌더에 `==강조==` → `<span class="hl">` 규칙을 한 줄 추가했다).

**수식 *안*에 색이 있으면 CSS 로는 안 된다. 그때는 확장을 번들에 이어 붙인다.**
preintegration 스터디의 원문은 `#a50000` 을 **수식 글리프**에 57구간 썼다(폰트가 CMMI/CMSY/CMEX 였다).
CSS 로는 수식 전체가 물들 뿐 일부만 칠할 수 없어 `\color` 가 꼭 필요했다.

해결은 간단하다 — **컴포넌트 파일을 번들 뒤에 이어 붙이고 `packages` 에만 더한다.**

```bash
curl -sO https://cdn.jsdelivr.net/npm/mathjax@3/es5/input/tex/extensions/color.js
curl -sO https://cdn.jsdelivr.net/npm/mathjax@3/es5/input/tex/extensions/boldsymbol.js
cat tex-svg.js color.js boldsymbol.js > _study_kit/tools/vendor/tex-svg.js
```

```js
window.MathJax = { tex: { packages: {'[+]': ['color', 'boldsymbol']}, ... } };
```

⚠️ **`loader: {load: ['[tex]/color']}` 로 부르면 안 된다.** 그러면 이미 로드된 코드가 있어도
로더가 네트워크를 타서 B6 에 그대로 걸린다 — 실제로 이 경로로 시도했다가 `<mjx-container` 0개를 봤다.
`<script>` 태그를 따로 두는 것도 위험하다(startup 프라미스가 그 사이에 끼어들 수 있다).
**한 파일로 이어 붙이는 것**이 확실하다. 버전은 번들과 맞춰라(여기서는 3.2.2).

같은 방법으로 `cancel.js` 는 **동작하지 않았다** — 붙여도 `<mjx-container` 가 0개였다.
새 확장을 붙일 때는 반드시 아래 최소 예제로 하나씩 확인하라.

```bash
# 확장마다 그 확장의 매크로만 쓴 페이지로 따로 시험한다.
# 한 페이지에 여러 매크로를 섞으면 로드 안 된 다른 매크로 때문에 전부 0 이 나와
# "붙였는데도 안 된다" 고 잘못 판단하게 된다 — 실제로 한 번 헤맸다.
```

**어두운 배경 보정** — `\color` 값은 SVG 에 `fill`/`stroke` **속성**으로 박힌다.
CSS 프로퍼티가 표현 속성을 이기므로 다크 테마에서만 밝은 값으로 덮어쓸 수 있다.

```css
:root[data-theme="dark"] [fill="#a50000"]   { fill:  #f2736b; }
:root[data-theme="dark"] [stroke="#a50000"] { stroke:#f2736b; }
```

**`\color` 는 두 인자를 받는다** (`\color{색}{수식}`). 인자 밖으로는 색이 새지 않으므로
`\color{black}` 으로 되돌릴 필요가 없다. `{\color{색} ...}` 그룹 형태도 동작하고
`\boxed{\begin{aligned}...\end{aligned}}` 안에서도 문제없다.

> **쿼터니언 스터디 사례** — 굵은 그리스 문자가 190곳 나오는 문서라 `\boldsymbol`을 그대로 두면
> 3.9MB 문서의 수식이 **하나도** 렌더링되지 않았다. 일괄 치환 후 976개가 정상 렌더링됐다.
>
> ```bash
> python3 -c "p='notes/노트.md'; s=open(p).read(); open(p,'w').write(s.replace(r'\boldsymbol', r'\pmb'))"

### B8. 강조 구간 안에 `=` 가 들어 있어 마크업이 깨졌다

**증상** — `==강조==` 를 113곳 썼는데 HTML 에는 `<span class="hl">` 이 111개만 나왔다.
눈으로는 어디가 빠졌는지 보이지 않는다.

**원인** — 빌더의 정규식이 `==([^=\n]+)==` 였다. 원문에 `트레이스 = 랭크:` 처럼 **강조 구간 안에
단일 `=` 가 들어가는** 문장이 있으면 매칭에 실패한다.

**대처** — 단일 `=` 는 허용하고 `==` 만 경계로 보게 고친다.

```python
text = re.sub(r"==((?:[^=\n]|=(?!=))+)==", r'<span class="hl">\1</span>', text)
```

**그리고 개수를 반드시 대조하라.** 마크업이 조용히 실패하는 종류의 버그다.

```bash
# md 의 == 개수 ÷ 2  ==  html 의 class="hl" 개수  여야 한다
python3 -c "s=open('notes/노트.md').read(); print(s.count('==')//2)"
python3 -c "s=open('notes/노트.html').read(); print(s.count('class=\"hl\"'))"
```

같은 이유로 **PDF 의 색 구간 개수와도 대조**한다. 색 있는 span 을 연속 구간으로 묶어 세면 된다
(구간이 쪽 경계를 넘어가면 두 번 세어지므로 그만큼 빼야 한다).

### B9. 목록 항목의 이어지는 줄을 들여쓰지 않아 인라인 마크업이 끊겼다

**증상** — `==강조==` 를 24곳 썼는데 HTML 에는 23개만 나왔다. B8 과 증상이 같지만 원인이 다르다.

**원인** — 마크다운 목록 항목이 여러 줄에 걸쳐 있었는데 **이어지는 줄을 들여쓰지 않았다.**

```markdown
- $\pi_c^{-1}(\cdot)$: back projection 함수. … ==VINS-mono
논문에서는 …                                       ← 들여쓰기 없음
때문으로 보인다==
```

`build_html.py` 는 목록 항목의 연속 줄을 **불릿보다 더 들여쓴 경우에만** 같은 항목으로 흡수한다
(`(len(lines[i]) - len(lines[i].lstrip())) > indent`). 들여쓰기가 없으면 목록이 거기서 끝나고
나머지는 별도 문단이 되므로, `==` 가 서로 다른 블록으로 갈라져 짝이 맞지 않는다.
`inline()` 은 문단 안에서만 `' '.join(buf)` 로 줄을 이어 붙이기 때문에 **문단을 넘는 마크업은 살지 못한다.**

**고치는 법** — 이어지는 줄을 두 칸 들여쓴다.

```markdown
- $\pi_c^{-1}(\cdot)$: back projection 함수. … ==VINS-mono
  논문에서는 …
  때문으로 보인다==
```

**미리 잡는 법** — 전사 후 아래를 돌려 보면 한 번에 나온다.

```python
import re
lines = open('notes/노트.md').read().split('\n')
for i, l in enumerate(lines):
    if re.match(r'^([-*]|\d+\.)\s+', l):
        j = i + 1
        while j < len(lines) and lines[j].strip() and \
              not re.match(r'^(\s*)([-*]|\d+\.)\s+', lines[j]) and \
              not lines[j].startswith(('#', '>', '```', '|', '$$', '<!--')):
            if not lines[j].startswith(' '):
                print('L%d 항목의 L%d 줄이 들여쓰기 없음' % (i+1, j+1))
            j += 1
```

같은 이유로 **`$$…$$` 안에서는 줄바꿈이 안전하다** — 수식은 문단 처리 전에 통째로 vault 에
들어가므로 여러 줄로 써도 깨지지 않는다. 산문 마크업만 조심하면 된다.

### B7. 절 번호를 임의로 만들지 않는다

## C. 위젯

### C1. 단위를 섞으면 조용히 망가진다 ⚠️ 찾기 어려운 버그

**증상** — 공분산 타원이 화면을 벗어날 만큼 커진다. 참값 대비 **2900% 과대**.
슬라이더로 노이즈를 줄여도 거의 변하지 않는다(← 이게 단서였다).

**원인** — 위젯이 **cm** 단위를 쓰는데, 모델 식의 계수는 **m** 단위를 전제한다.
$\alpha_3 v^2$ 항에서 $v$가 40(cm/s)이면 $v^2 = 1600$, m/s였다면 $0.16$ — **10⁴배**다.

**대처** — 위젯의 단위를 정하고 **모델 식이 그 단위를 전제하는지 확인**한다. 확실하지 않으면
교차 항을 0으로 두어 단위에 무관하게 만든다. 그리고 그 이유를 코드에 주석으로 남긴다.

> **일반화**: 슬라이더를 움직여도 결과가 안 변하면 그 항이 다른 항에 압도당하고 있다는 뜻이다.
> 각 항의 크기를 실제로 찍어 보라.

### C2. 화면 범위 계산에 그리려는 것을 빠뜨린다

**증상** — 타원이 직선처럼 보인다. 사실은 화면 밖으로 나가 일부만 보인 것이었다.

**원인** — 화면 범위를 표본점만으로 계산하고, 타원 반경을 포함하지 않았다.

**대처** — 범위 계산에 **그릴 모든 것**(타원 2σ 반경, 궤적, 랜드마크)을 넣는다.

### C3. 초기 렌더링만 확인하면 부족하다

**증상** — 페이지를 열었을 때는 멀쩡한데 버튼을 누르면 깨진다.

**대처** — 헤드리스로 **버튼 전부 클릭 + 슬라이더 극단값**까지 돌리고 오류·NaN을 확인한다.

### C4. 자코비안을 수치미분과 대조할 때는 **섭동 규약을 먼저 못 박는다** ⚠️ 찾기 어려운 버그

**증상** — 원문 식 (62) 를 수치미분과 대조했더니 상대오차가 **108** 이 나왔다.
"원문이 틀렸다"고 결론 내리기 직전이었다.

**원인** — 틀린 것은 검산 쪽이었다. 나는 $\mathbf{X}' = \mathrm{Exp}(\Delta\mathbf{w})\mathbf{R}\mathbf{X} + \mathbf{t}$
로 흔들었는데, 식은 $\mathbf{X}' \leftarrow \mathrm{Exp}(\Delta\mathbf{w})\mathbf{X}' + \Delta\mathbf{t}$
(포즈 전체에 대한 좌섭동)를 전제한다. 회전을 $\mathbf{R}$ 에만 거느냐 $\mathbf{X}'$ 전체에 거느냐가
$[\mathbf{t}]^\wedge$ 만큼 차이를 만든다.

**대처** — 후보 규약을 **전부 코드로 돌려 보고** 어느 것이 맞는지 결정한다.
그리고 그 비교 자체를 위젯의 버튼으로 남긴다. 6번 스터디에서 이 방식으로

| | 후보 | 상대오차 |
|---|---|---|
| (a) | $\mathrm{Exp}(\Delta\mathbf{w})\mathbf{R}\mathbf{X}+(\mathbf{t}+\Delta\mathbf{t})$ | 1.1e+2 |
| (b) | $\mathrm{Exp}(\Delta\mathbf{w})\mathbf{R}(\mathbf{X}+\mathbf{t}+\Delta\mathbf{t})$ ← 문서 (52) 정의 | 6.9e+1 |
| (c) | $\mathrm{Exp}(\Delta\mathbf{w})\mathbf{X}'+\Delta\mathbf{t}$ ← 표준 좌섭동 | **2.9e-8** |

를 얻어, "(52) 는 유도용 중간 표기이고 (61) 은 표준 좌섭동"이라고 결론지을 수 있었다.
같은 방식으로 식 (128) 도 좌섭동(1.5e-10) 이지 우섭동(2.0e+0) 이 아님을 확인했다.

**부산물** — 규약을 확정하고 나면 남는 오차는 **진짜** 오류다. 이 절차로 원문의 어긋남
세 곳(식 178 두 곳, 식 199 한 곳)을 찾았다.

### C5. 블록으로 쪼갠 자코비안은 **조각별로도** 대조한다

**증상** — 네 조각을 곱한 최종 자코비안은 수치미분과 맞는데, 중간 조각 하나가 틀려 있었다.

**원인** — 두 군데 오류가 서로 상쇄되면 곱만 봐서는 드러나지 않는다.

**대처** — 사슬의 **각 조각을 독립적으로** 수치미분과 대조한 뒤 곱도 대조한다.
6번 스터디의 실험 10 은 (148)(149)(150)(151)(152) 다섯 조각과 곱 두 개를 각각 찍는다.

또 하나 — $[\cdot]_{3\times3}$ 같은 **절단 표기의 순서**에 주의한다.
$4\times4$ 곱을 먼저 하고 절단하는 것과, 각 $3\times3$ 블록을 곱하는 것은 다르다
(6번 스터디 식 178 에서 상대오차 1.2e-10 vs 1.5e-2 로 갈렸다).

### C6. 위젯이 주장하는 경향은 **여러 시드로 재고 나서** 쓴다

**증상** — "블러를 키우면 광도 오차의 수렴 반경이 넓어진다"는 위젯을 만들었는데,
시드를 바꾸니 반대로 나오는 경우가 있었다.

**원인** — 단일 장면에서 잰 "계곡 반폭"은 잔무늬가 어디 놓였느냐에 좌우된다.
경향은 실재하지만 한 표본으로는 보이지 않는다.

**대처** — 시드 6개 평균 **성공률**로 바꿔서 재니 단조로운 경향이 나왔다
(오프셋 ±20px 에서 76% → 100%). 그리고 **"개별 시드로는 단조롭지 않다"는 사실 자체를
위젯 설명에 적었다.** 위젯이 거짓 확신을 주는 것보다 낫다.

### C7. 수식 자동 축소는 **재보고 다시 줄여야** 한다 ⚠️ 찾기 어려운 버그

**증상** — 넘치는 수식을 폰트 크기로 줄이는 코드를 넣었는데, 창 폭에 따라 여전히
몇 픽셀씩 넘치는 수식이 남았다. 안전계수를 0.99 → 0.97 로 낮춰도 사라지지 않았다.

**원인 두 가지.**

1. **판정 대상이 틀렸다.** `mjx-container` 의 `getBoundingClientRect().width` 를 재고 있었는데,
   display 수식의 컨테이너는 블록이라 폭이 부모와 같게 잡히는 경우가 있다.
   그 결과 **넘치지 않는 수식까지 전부 축소 대상**이 되었다 (7번 스터디에서 101개 전부).
   실제로 넘치는지는 박스 자신의 `scrollWidth > clientWidth` 로 봐야 한다.
2. **폰트 크기와 렌더 폭이 정확히 비례하지 않는다.** MathJax SVG 는 글리프 폭을
   반올림하고 일부 요소에 최소폭이 있어서, 0.82 배로 줄여도 예상보다 몇 px 넓게 나온다.
   한 번 계산으로는 맞출 수 없다.

**대처** — 판정을 `box.scrollWidth` 로 바꾸고, 설정 후 **다시 재서 남은 넘침만큼 또 줄이는
루프**를 돌린다 (하한에 걸리면 중단).

```js
if (box.scrollWidth > box.clientWidth + 1) {
  var ratio = Math.max(MIN, (avail / need) * 0.97);
  box.style.fontSize = (ratio*100).toFixed(1) + '%';
  for (var pass = 0; pass < 6 && ratio > MIN; pass++) {
    var over = box.scrollWidth - box.clientWidth;
    if (over <= 1) break;
    var w = box.clientWidth - 2;
    ratio = Math.max(MIN, ratio * (w / (w + over)) * 0.99);
    box.style.fontSize = (ratio*100).toFixed(1) + '%';
  }
}
```

고친 뒤 7번 스터디는 폭 820~1920px 전 구간에서 **넘침 0**, 축소되는 수식은 1~5개뿐이 되었다.

**검증할 때** — 넘침 개수만 보지 말고 **축소된 수식 개수도 같이 찍어라**.
"넘침 0"인데 전부 축소되어 있으면 판정이 틀린 것이다.

### C8. 위젯이 원문 공식을 그대로 쓰기 전에 **그 공식의 해석부터 확인한다**

**증상** — 원문의 "2D 법선은 $\mathbf{n} = [-y, x]^\intercal$" 를 글자 그대로 구현했더니
point-to-plane ICP 성공률이 9% 로 나왔다. 위젯이 고장난 줄 알았다.

**원인** — 공식은 맞지만 **무엇에 적용하는지**가 문제였다. 점의 *위치 벡터*를 90° 돌린 것은
표면 법선이 아니다 (PCA 법선과 중앙값 58° 차이). 같은 공식을 *이웃 차분 벡터*
$\mathbf{p}_{i+1}-\mathbf{p}_{i-1}$ 에 적용하면 8.6° 차이에 성공률 91% 가 된다.

**대처** — 후보 해석을 **전부 구현해서 나란히 재고**, 그 비교 자체를 위젯으로 남긴다.
"원문이 틀렸다"와 "원문을 잘못 읽었다"를 숫자로 갈라 놓아야 한다. (C4 와 같은 태도다.)

### C9. 좁은 창에서 본문이 옆으로 밀리면 **범인은 수식 상자가 아니다** ⚠️ 찾기 어려운 버그

**증상** — 창을 480px 로 좁히면 `document.body.scrollWidth` 가 뷰포트보다 56~119px 크다.
가로 스크롤바가 생기고 본문 전체가 밀린다. 그런데 `.mathblock` 은 `overflow-x:auto` 라
넘치는 수식은 자기 상자 안에서 스크롤될 뿐이다. 넘치는 수식을 아무리 찾아봐도 원인이 아니다.

**원인 — 세 가지가 따로 있었고, 셋 다 `.mathblock` 밖이었다.**

1. **줄바꿈이 불가능한 인라인 수식.** `$\det(2\ 3\ 4)c_1 - \cdots = 0$` 같은 식은
   `.mathblock` 같은 스크롤 상자가 없어 그대로 폭을 밀어낸다.
   자동 축소를 인라인에도 걸어야 하는데, 이때 **부모가 `<span class="hl">` 이면
   `clientWidth` 가 0** 이다 (인라인 요소). 블록 조상까지 올라가서 재야 한다.
2. **`mjx-assistive-mml`.** MathJax 가 넣는 보조 MathML 은
   `position:absolute; width:auto` 라 **조상의 `overflow:auto` 클리핑을 빠져나간다**.
   화면에는 `clip` 으로 감춰져 있어 눈에 보이지 않는데 레이아웃 폭만 밀어낸다.
   → 레이아웃 폭을 `1px` 로 묶는다.
3. **링크로 파싱되지 않은 긴 URL.** 링크 정규식 `\[([^\]]+)\]\(...\)` 은
   `[(Blog) [SLAM] 제목](url)` 처럼 **텍스트 안에 대괄호가 든 링크**에서 실패한다.
   그러면 원시 마크다운(=긴 URL 통짜)이 본문에 그대로 남아 안 접힌다.
   → 한 겹 중첩까지 허용하도록 고친다.

**찾는 법** — "오른쪽 끝이 뷰포트를 넘는 요소"를 훑으면 **클리핑된 것까지 잡혀 헛짚는다**.
가장 빠른 것은 **자식을 하나씩 `display:none` 해 보며 `scrollWidth` 가 줄어드는 놈을 찾는 것**이다.

```js
var wrap = document.querySelector('.wrap'), base = wrap.scrollWidth;
[].slice.call(wrap.children).forEach(function (el, i) {
  var d = el.style.display; el.style.display = 'none';
  if (wrap.scrollWidth < base - 1) console.log(i, el.tagName, el.className, wrap.scrollWidth);
  el.style.display = d;
});
```

**대처** — 빌드 뒤 **창 폭 1440/900/700/480/360px 掃引**을 고정 절차로 넣는다.
`본문가로 넘침 = 0` 이 아니면 위 세 가지부터 본다.
셋 다 `build_html.py` 에 고쳐 두었고 아홉 킷에 동기화했다.

## D. 환경

### D1. `pip`이 없다

**증상** — `pip install pdfplumber`가 `command not found`.

**대처** — apt로 설치한다. 필요한 것은 대개 이 둘이다.

```bash
sudo apt install -y python3-fitz     # PyMuPDF
sudo apt install -y python3-numpy
```

`pdfplumber`는 apt에 없다. **PyMuPDF로 충분하다** — 오히려 렌더링·클리핑까지 한 번에 되어 낫다.

### D2. 노트의 코드가 그 환경에서 안 돌 수 있다

**증상** — 노트에 numpy 예제를 넣었는데 정작 그 머신에 numpy가 없다.

**대처** — 스니펫 첫 줄에 설치 명령을 주석으로 적고, `1_Tools.md`에도 "읽고 빌드하는 데는
불필요, 스니펫 실행에만 필요"를 밝힌다.

---

### D3. `check_refs.py` 가 "이상 없음"인지 "아무것도 못 읽었는지" 구분한다

**증상** — 노트에 있는 절 번호가 전부 "목차에 없는 절"로 나왔다.

**원인** — `toc_sections()` 의 정규식이 `- 2.1 …` 형식만 읽는데, `0_Contents.md` 를
표(`| 2.1 | … |`)로 썼다. 절을 **0개** 수집하고도 조용히 진행한 것이다.

**대처** — 정규식을 `^\s*[-|]?\s*(\d+\.\d+(?:\.\d+)?)\s*[\s|]` 로 고쳐 두 형식을 모두 읽게 했다.
그리고 출력 첫 줄에 찍히는 **"목차 절 N개 수집"의 N 을 반드시 확인한다** — 0 이면 검사가 아니라 무검사다.

### D4. 빌드된 HTML 에 `</body>` 가 없다 — 헤드리스 프로브는 **파일 끝에 붙인다**

**증상** — 검증 스크립트를 `dom.replace('</body>', probe + '</body>')` 로 주입했는데
아무 출력도 없었다. 페이지는 8MB 나 로드되는데 프로브만 실행되지 않았다.

**원인** — `build_html.py` 가 닫는 `</body>` 를 쓰지 않는다. `replace` 가 조용히 실패했다.

**대처** — `io.open(...).write(dom + probe)` 로 **끝에 이어 붙인다**.
그리고 주입이 됐는지 `grep -c '__probe' probe.html` 로 먼저 확인한다 — 0 이면 실행 전에 안다.

### D5. 헬퍼를 복사해 이름만 바꿀 때 **IIFE 대입문을 잘라먹지 않도록**

**증상** — 새 스터디용 헬퍼 `_ic_helper.js` 를 만들고 위젯을 열었더니
`Cannot read properties of undefined (reading 'eigSym')`.

**원인** — 헤더 주석을 갈아 끼우려고 `s.index('(function')` 로 잘랐는데,
그 바로 앞에 있던 `window.EJ = ` 가 같이 날아갔다. 파일은 문법적으로 멀쩡해서
(익명 IIFE 가 실행되고 버려질 뿐) 에러가 나지 않고, 쓰는 쪽에서야 터진다.

**대처** — 자르지 말고 **치환**한다.

```python
s = s.replace('\n(function () {', '\nwindow.IC = (function () {', 1)
```

그리고 헬퍼를 만든 직후 `grep -n 'window\.[A-Z]* = (function' helper.js` 로
전역 대입이 살아 있는지 한 번 본다.
